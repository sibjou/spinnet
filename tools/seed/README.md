# Тестовые данные для Spinnet

Скрипт наполняет Firestore правдоподобными данными: для скриншотов и для проверки скорости на большой базе.

## Что создаётся (масштаб 1)

| | |
|---|---|
| Игроки | 120 человек из Томска, Новосибирска, Москвы, Санкт-Петербурга, Кемерова и Мурманска: разный уровень, хват, стиль, рейтинг TTW, настройки приватности, «был(а) в сети» |
| Заявки | ~700: 220 в ленте, 45 с бронью на будущее, 340 сыгранных, остальные истекли или отменены. Около десяти авторов создают по 20–50 заявок, у самых активных одновременно открыто 12–17 |
| Матчи | ~360 со счётом по партиям; подтверждённые, ждущие ответа и оспоренные; у части встреч несколько матчей |
| Отзывы | ~430 с оценками 1–5 (в основном 4–5), у половины есть текст |
| Турниры | 48: прошедшие и предстоящие, во всех городах, от 8 до 64 мест, часть заполнена |

Если указать свой аккаунт (`--me-uid`), к нему добавляется ещё и «жизнь»: ~60 сыгранных игр за год с лишним (есть фильтры и группы по месяцам в профиле), матчи, которые ждут вашего ответа, отзывы о вас, игры на ближайшие дни, игра «вчера» без счёта и отзыва, пара отмен, пять турниров (один организуете вы) и уведомления.

## Что настоящее, а что придумано

- **Настоящие**: площадки — клубы настольного тенниса и спорткомплексы с адресами из открытых каталогов (`data/venues.json`, у каждой записи указан источник и насколько надёжен адрес). Список собран 13 октября 2026; адреса могут измениться, а наличие столов в спорткомплексах не проверялось — прежде чем публиковать скриншоты, сверьтесь с картой.
- **Придуманные**: все люди (совпадения имён случайны), их результаты, отзывы, заявки, организаторы и сами турниры. Названия турниров общие («Турнир выходного дня», «Осенний кубок любителей»…) — это не расписание настоящих соревнований, и клубы не названы их организаторами.
- Почты — вида `ekaterina.zimina@spinnet.test`. Домен `.test` зарезервирован: настоящих адресов и писем не бывает.
- У каждого игрока есть настоящий аккаунт Firebase Authentication с этой почтой, поэтому под ним можно войти в приложение (например, чтобы сделать скриншот чужого профиля или проверить бронирование с другой стороны). Один случайный пароль на всех появляется в терминале и в `out/accounts.csv` (файл в `.gitignore`, права только у вас).

## Подготовка

1. Python 3.9+ и пакет:
   ```bash
   cd tools/seed
   pip3 install -r requirements.txt
   ```
2. Ключ сервисного аккаунта: Firebase Console → Project settings → Service accounts → **Generate new private key**. Файл не добавляйте в репозиторий (шаблоны имён уже в `.gitignore`) и после работы удалите.
3. Свой uid: Firebase Console → Authentication → Users → колонка «User UID».

## Использование

Сначала посмотрите, что получится, — в базу ничего не пишется:

```bash
python3 seed.py plan --me-uid <ВАШ_UID> --me-first Имя --me-last Фамилия
```

Сводка появится в терминале, все документы — в `out/plan.json`.

Запись:

```bash
python3 seed.py apply --project spinnet-30103 --key ~/Downloads/key.json \
    --me-uid <ВАШ_UID> --me-first Имя --me-last Фамилия
```

Скрипт проверит, что ключ от этого проекта, и попросит ввести id проекта: **это настоящая база приложения**. Если тестовые данные там уже есть, он остановится. В конце он создаёт аккаунты для входа и печатает пароль; список адресов — в `out/accounts.csv`. Свой пароль можно задать через `--password` или переменную `SEED_PASSWORD` (так он не попадёт в историю команд).

Пока идёт тестирование, это настоящие аккаунты в Authentication вашего проекта: не публикуйте пароль и удалите всё командой `clean`, когда скриншоты готовы.

Удаление всего добавленного:

```bash
python3 seed.py clean --project spinnet-30103 --key ~/Downloads/key.json --me-uid <ВАШ_UID>
```

`clean` удаляет документы с полем `isSeed: true`, ваши тестовые уведомления (с `--me-uid`) и аккаунты Authentication, у которых uid начинается с `seedu` и почта на `@spinnet.test`. Ваши настоящие заявки, отзывы, профиль и аккаунт не затрагиваются. Чтобы сначала увидеть, сколько будет удалено, добавьте `--dry-run`.

### Параметры

| | |
|---|---|
| `--scale 5` | пятикратный объём (~600 человек, ~3 500 заявок) — для проверки скорости ленты, профилей, турниров |
| `--seed 7` | другой набор людей и результатов (при тех же числах набор повторяется) |
| `--tz 7` | часовой пояс телефона для скриншотов: от него зависит «сегодня» и время ближайших игр |
| `--me-city`, `--me-skill` | город и уровень вашего аккаунта (по умолчанию Томск, Любитель) |
| `--no-auth` | только документы Firestore, без аккаунтов для входа (для `apply` и `clean`) |
| `--password` | свой пароль для всех тестовых аккаунтов вместо случайного |
| `--email-domain` | другой домен почты (по умолчанию `spinnet.test`; для `clean` указывайте тот же) |

## Советы для скриншотов и замеров

- Даты считаются от дня запуска: ближайшие игры, «сегодня», «вчера». Через несколько недель удобнее выполнить `clean` и `apply` заново.
- Замер запуска: соберите схему в режиме Release (или Profile) на устройстве и смотрите в консоль строки `⏱ +412 мс …` — в Debug запуск заведомо медленнее. Для сравнения запустите `apply` с `--scale 1`, снимите время, затем `clean` и `apply --scale 5`.
- Сначала войдите под своим аккаунтом, чтобы лента и профиль открылись в вашем городе; под почтой из `out/accounts.csv` можно войти и за любого из тестовых игроков.
- Фильтр «Город» в ленте: все шесть городов заполнены, в Томске заявок больше всего.

## Проверка самого скрипта

```bash
cd tools/seed
python3 -m unittest discover -s tests
```

Тесты проверяют, что почты уникальны и на тестовом домене, что аккаунты создаются и удаляются только свои (запись и удаление проверены на подделках Firestore и Authentication), что каждый матч возможен по правилам настольного тенниса (порт `MatchScoring`), что игры, отзывы и турниры согласованы между собой, что ничего не «создано в будущем», и что набор повторяется при тех же параметрах. Дополнительно сгенерированные матчи прогонялись через настоящий `Match` и `MatchScoring` из приложения.
